# Проверка решений агента

Это отдельный набор задач словами, без готовых spec. Он не входит в метрику
интеграционного `run_eval.py` и выполнен тремя независимыми агентами 14.11.2026.
Итог и ограничения — [RESULTS.md](RESULTS.md).

Для каждого случая из cases.json начни чистый контекст. Передай агенту только `task`,
SKILL.md и минимальные исходные артефакты: явно выбранное тестовое подключение,
схему/профиль, исходный граф для правки или тестовый документ, если они нужны.
Поле acceptance оставь оценщику, не передавай агенту ожидаемый план или исправления.
Не используй рабочую БД/флоу; внешние эффекты ограничь отдельным тестовым стендом.
Для офлайн-случая не подключай live-инструменты.

Сохрани исходное состояние, диалог, tool calls, итоговый граф и результаты запусков.
Оцени пункты acceptance по наблюдаемым артефактам, а не по заявлению агента.
Для B02 сравни IDs, связи и незатронутые поля до/после; для B05 нужен trace вызова;
для B06 нужны session IDs и ответы всех ходов. Не собирай секреты в отчёт.

Метрики: доля успешно решённых задач, ошибки первой spec, число ненужных вопросов,
число повторных вызовов схем неизменного типа, число запусков и сохранность исходных
параметров. Публикуй число прогонов, среду, непроверенные пункты и сырые доказательства.
Сравнение с агентом без скилла и несколько повторов позволяют измерить пользу инструкций.
