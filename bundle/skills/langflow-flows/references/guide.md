# Курс: словарь, блоки, грабли

Материал из учебного гайда по Langflow. Здесь то, чего обычно нет в документации:
названия блоков «как их называют на курсе», поведение на границах и точные тексты ошибок.

**Важно:** привязки к конкретной установке (какой провайдер, какие лимиты, что запрещено)
здесь нет намеренно — это живёт в профиле стенда (`profiles/<id>/profile.md`).
Ниже — наблюдения автора курса, зависящие от его версии и компонентов.
Порты и поведение надо сверять с целевым стендом; статус запуска — в `VERIFICATION.md`.

## Словарь: как называют на курсе → что это в графе

| На курсе | Тип компонента | Ключевое |
|---|---|---|
| Модель | `ext:openai:OpenAIModelComponent@official` | блок OpenAI-совместимого провайдера; куда идёт запрос — задаёт `openai_api_base` |
| Model Response (выход) | `text_output` | выполняет запрос, отдаёт текст |
| Language Model (выход) | `model_output` | **не вызывает** модель, а передаёт её настройки другому блоку |
| Промпт | `Prompt Template` | `{переменная}` = вход блока |
| If-Else | `ConditionalRouter` | `true_result` / `false_result` |
| Развилка по теме | `SmartRouter` | категории из поля Routes → отдельные выходы |
| Message History | `Memory` | режим Retrieve отдаёт историю текстом |
| Loop / Цикл | `LoopComponent` | порты `item`, `∞`, `done` |
| Подтверждение | `HumanInput` | пауза, варианты решения = выходы |
| Подпоток | `RunFlow` | Beta; поля входных блоков появляются на блоке |
| Batch Run | `BatchRunComponent` | модель по строкам таблицы, без цикла |
| Structured Output | `StructuredOutput` | поля по схеме |
| Parser | `ParserComponent` | данные → текст по шаблону |
| Type Convert | `TypeConverterComponent` | Message ↔ JSON ↔ Table |
| Read / Write File | `File` / `SaveToFile` | запись зависит от политики установки |
| Web Search | `UnifiedWebSearch` | Web / News / RSS |
| API Request | `APIRequest` | HTTP, ответ в поле `result` |

## Ограничения установки

Лимиты времени и параллельности, политика записи файлов, доступные форматы, поддержка
изображений — это свойства **стенда**, а не Langflow. Их не угадывают: смотри
`profiles/<id>/profile.md`, раздел «Ограничения». Если профиля нет — сними его
(`references/recon.md`).

Типичные вопросы, на которые отвечает профиль:

- сколько живёт один запуск и где обрывается;
- сколько запросов к модели можно пускать одновременно;
- разрешена ли запись файлов и куда;
- читает ли `File` xlsx, таблицы в docx и сканы;
- есть ли выход в интернет и что блокируется;
- какие модели понимают изображения.

## Блоки: что важно знать

**Модель (OpenAI).** Запрос уходит по `openai_api_base`, поэтому «OpenAI» здесь — это
формат обмена, а не обязательно сервис OpenAI. Конкретные адрес, имя модели и переменная
с ключом — в профиле стенда. Имя модели часто содержит каталог/проект, и он должен
совпадать с тем, к которому выпущен ключ.

**Language Model** (Models & Agents) — список только тех провайдеров, что настроены
в Settings. Если нужного провайдера там нет, для агента берут блок из Bundles
и его выход `model_output`.

**Agent.** `max_iterations` по умолчанию **15**; на лимите ответ
`Model call limits exceeded: run limit (15/15)`. Инструменты «калькулятор» и «текущая дата»
включены всегда, даже при пустом входе Tools. Без модели — `No model selected…`.
Если вход идёт через Prompt Template, реплика пользователя может попасть в запрос дважды
(из истории и из промпта).

**Prompt Template.** Каждое `{слово}` — вход. Пустая переменная подставляется пустой строкой
без ошибки. Занятые имена: `status`, `code`, `template`, `template_format`, `input_variables`,
`output_parser`, `partial_variables`, `validate_template`. Имена без пробелов и знаков,
не с цифры и не с подчёркивания. JSON с фигурными скобками в промпте создаёт лишние
переменные — включайте `use_double_brackets`. Вход принимает только Message: данные
сначала через Parser.

**If-Else.** Операторы `equals`, `contains`, `starts with`, `ends with`, `regex`,
`less/greater than`. **Regex сверяет с начала строки** — начинайте с `(?s).*`;
без учёта регистра `(?i)`. Неверное выражение ошибки не даёт: условие просто не выполнено.
`less than` / `greater than` переводят в числа: «12,5» с запятой числом не считается
и условие молча не выполняется. Срабатывания считаются: на проходе с номером
`max_iterations` поток уходит на `default_route` с пустым текстом.

**Loop.** Вход `data` → выход `item` (по строке) → тело цикла → последний блок тела
возвращается в порт `∞`; после последней строки `done` отдаёт таблицу с колонкой `text`.
Рано прервать нельзя. Ошибка в любой строке останавливает весь цикл
(`Error in loop iteration: …`). `item` — это Data, для промпта нужен Parser.
Без связи в `∞` тело не запустится, `done` пуст.

**Human Input.** Поток встаёт, в Playground появляются кнопки. Каждый вариант из
`user_choices` — отдельный выход (`branch_approve`, `branch_reject`). Пока решения нет,
блоки после паузы пусты — это норма. Внутри Run Flow не работает.

**Smart Router.** Категории задаются списком `routes`, для каждой строки появляется выход.
Нужна модель на входе `model`. Ответ модели сравнивается с именами без учёта регистра;
`NONE` или лишний символ → ветка Else. Каждый запуск тратит один запрос к модели.

**Structured Output.** Поля задаются таблицей `output_schema`. Один объект → запись с полями;
несколько объектов → запись с одним полем `results` (поэтому Parser с `{поле}` даст пусто —
берите выход Table).

**Batch Run.** Отправляет модели по строке таблицы параллельно, ответ дописывает колонкой.
Сбой по любой строке останавливает весь блок, частичного результата нет.
Имя колонки должно совпадать: `Column 'имя' not found in the DataFrame. Available columns: …`.

**Message History.** Режим Retrieve отдаёт `messages_text` в виде «Имя: сообщение» только
по этой сессии, этому потоку и этой учётке. Сообщения сохраняют сами Chat Input и Chat Output,
поэтому режим Store обычно не нужен. Схема диалога: `Memory.messages_text → Prompt.history`,
`Prompt.prompt → Model.system_message`, `ChatInput.message → Model.input_value`.

**Run Flow.** Beta. Выбирается поток того же проекта; после импорта выбирать заново.
Ошибка внутри — общей фразой `Error running flow: имя`, причину смотреть запуском подпотока.
Human Input внутри подпотока невозможен.

**API Request.** Ответ — запись с `source`, `status_code`, `response_headers`, `result`.
Ошибка сервиса поток **не** останавливает: проверяйте `status_code`. Адреса внутренней сети
заблокированы (`SSRF Protection`). В Tool Mode модель заполняет только адрес/curl.

**Read File.** Читает pdf с текстовым слоем, docx, txt, md, csv, json, yaml, xml, html.
xlsx/pptx/картинки требуют Advanced Parser (пакета нет). После импорта потока
файл нужно выбрать заново (`No files to process`).

**Python Interpreter.** Отдаёт только то, что напечатано через `print`. `import` в коде
запрещён — модули в `global_imports`. `open`, `eval`, `exec` недоступны. Ошибка не
останавливает поток: она в поле `error` или текстом в `result`.

**Calculator.** Только `+ - * / **` и скобки, шесть знаков, отрицательные числа не считаются.

## Что из этого важнее всего для скилла

1. **Model Response против Language Model** — самая частая причина «агент молчит»
   и запроса не туда, куда планировали.
2. **Regex в If-Else якорится на начало строки** — без `(?s).*` не сработает.
3. **Цикл требует связи в `∞`**, иначе тело не запускается, а ошибки нет.
4. **Structured Output с несколькими объектами** отдаёт `results`, а не поля.
5. **Проверяйте `status_code` у API Request** — ошибка не останавливает поток.
