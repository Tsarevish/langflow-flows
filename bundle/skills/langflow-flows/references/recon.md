# Разведка стенда

Скилл общий, стенды разные. Всё, что зависит от конкретной установки — версия, провайдеры,
лимиты, политика записи файлов, — живёт **не в правилах скилла, а в профиле стенда**.
Правила ссылаются на профиль, а не наоборот.

## Когда снимать профиль

- Профиля нет (`profiles/` пуст).
- Профиль есть, но версия Langflow в нём не совпадает с текущей.
- Профиль есть, но задача упирается в то, чего в нём нет (лимиты, форматы файлов).

Если стенд недоступен — работай по общим правилам и **скажи**, что профиль не снят:
часть рекомендаций может не подойти.

## Шаг 1. Автоматически

```
python scripts/probe_stand.py                     # URL и ключ из ~/.langflow/env
python scripts/probe_stand.py --env ~/.langflow/env.local
python scripts/probe_stand.py --url URL --key KEY
```

Для второго и последующих стендов — отдельный файл окружения (`--env`), а не правка
основного: иначе ключи перепутаются.

Пишет в `profiles/stand-<host>/`:

| Файл | Что внутри |
|---|---|
| `profile.md` | карточка стенда: доступ, версия, флаги, модели, MCP, ограничения |
| `profile.json` | то же машинно |
| `components.json` | снапшот схем — по нему работает `validate_spec.py` |

Скрипт определяет сам: версию, аутентификацию и роль, флаги (`allow_custom_components`,
`authz_enabled`), список провайдеров, настроенные переменные, наличие встроенного MCP
и число его инструментов, количество компонентов и флоу.

## Если стенд локальный

Локальная установка ставит свои вопросы, которых нет у серверной.

**Найти.** Порт по умолчанию — 7860; перебрать соседние (7861, 7862, 8000, 8080, 3000)
и проверить `GET /api/v1/version`. Отвечает `{"version": …}` — это он.

**Проверить, что доступно без ключа.** `/api/v1/version`, `/health`, `/api/v1/config`,
`/openapi.json` обычно открыты. Всё остальное — 403.

**Получить ключ.** С версии 1.5 авто-логин не ослабляет API: без ключа ответ будет

```
Since v1.5, LANGFLOW_AUTO_LOGIN requires a valid API key.
Set LANGFLOW_SKIP_AUTH_AUTO_LOGIN=true to skip this check.
```

Ключ создаётся в интерфейсе: аватар → Settings → Langflow API → Add New.
Логин `langflow/langflow` на авто-логине не работает — суперюзер создаётся со случайным
паролем.

**Учесть локальные особенности.** Файлы на диске сервер может и писать (в отличие от
общего стенда), доступ в интернет обычно есть, а вот модели — только те, чьи ключи
заведены: у локальной установки нет «корпоративного» шлюза, который настроен на сервере.

## Шаг 2. Спросить у человека

Дешевле, чем выяснять опытом. Одним сообщением:

> Снимаю профиль стенда. Три вопроса, на которые из API не ответить:
> 1. Есть ли лимит на длительность одного запуска?
> 2. Сколько запросов к модели можно пускать одновременно?
> 3. Можно ли потоку писать файлы и куда?

## Шаг 3. Проверить опытом — что реально стоит проверять

Каждый опыт — отдельный одноразовый флоу, который удаляется после.

**Доступ в интернет с сервера.** `APIRequest` на `https://httpbin.org/get` (или любой
внешний адрес) → смотри `status_code` в выходе. `500` и поле `error` значат, что выхода нет.
Адреса внутренней сети блокируются защитой SSRF — это нормально и ожидаемо.

**Запись файлов.** Флоу `ChatInput → SaveToFile → ChatOutput`, короткий текст на вход.
`Permission denied` = запись запрещена; успех = можно, и в ответе будет имя файла.

**Чтение форматов.** `File` с маленьким xlsx, затем с docx, где есть таблица.
Сообщение `requires Advanced Parser` = формат не читается штатно.

**Права на кастомные компоненты.** Создать пустой кастомный компонент и удалить.
Отказ = путь закрыт, планируй только из готовых блоков.

**Лимит времени.** Дорогой опыт: запусти заведомо долгий прогон (большой файл или длинный
ответ) и смотри, обрывается ли он с сообщением о превышении. Если обрывается — зафиксируй
порог с запасом и в следующий раз режь работу на части.

**Параллельные запросы.** Проверять дорого (Batch Run на десятках строк). Обычно достаточно
ответа человека: лимит нужен, чтобы не строить широкие ветвления.

## Шаг 4. Записать в профиль

В `profile.md` заполни два раздела:

```markdown
## Ограничения
| Что | Значение | Следствие |
|---|---|---|
| Один запуск | 300 с | резать работу на части |
...

## Особенности
- Write File запрещён: Permission denied. Вывод — в чат.
- xlsx не читается без Advanced Parser.
```

Правило: **каждый факт с пометкой источника** — «проверено запросом», «из документации»,
«со слов владельца». Через месяц это сэкономит повторную разведку.

## Шаг 5. Держать в актуальном состоянии

- Сменилась версия → перегенерируй `components.json` (`probe_stand.py` или `dump_schema.py`):
  имена компонентов и портов меняются между версиями.
- Появился новый провайдер или переменная → обнови раздел «Модели».
- Обнаружил новую особенность в работе → допиши, а не держи в голове.

## Чего не делать

- Не переносить факты стенда в `SKILL.md`, `references/errors.md` и другие общие файлы.
  Общее правило звучит «проверь лимит запуска в профиле», а не «лимит 300 секунд».
- Не строить профиль по документации Langflow: документация описывает платформу,
  а не эту установку с её прокси, лимитами и правами.
- Не считать профиль истиной навсегда: он снимок на дату, и дата в нём есть.
