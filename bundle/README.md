# dsh-langflow-flows-skill

Плагин-бандл DSH: приносит скилл `langflow-flows` в профиль и показывает бандл
в разделе «Плагины».

Автор скилла — **Andrey Datsenko**.

## Статус

Проверено на DSH 0.2.2-rc.1 (сборка из `app.asar`):

| Что | Результат |
|---|---|
| установка через `plugin_manager` | работает |
| запись в «Плагинах», версия, включение | работает |
| файлы скилла внутри пакета | на месте |
| автоматическая регистрация скилла патчем | **не работает** |

Патч-слой бандла применяется (в инвентаре видно `overrides: ["skill-filesystem"]`),
но значение `customSkillDirs` не доходит до провайдера скиллов: скилл в каталоге
не появляется. Проверены три варианта — отдельный провайдер, расширение списка
двумя `!!js`-элементами, одно `!!js`-выражение, возвращающее массив. Ни один не сработал:
похоже, в этой сборке значения `!!js` внутри `insert`/`override` из пользовательского
бандла не вычисляются так, как в базовых патчах.

## Как поставить скилл после установки бандла

Одна команда — ставит скилл из пакета в пользовательский каталог скиллов:

```
powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\dsh-langflow-flows-skill\skills\langflow-flows\scripts\install.ps1"
```

macOS / Linux:

```
~/.dsh/profiles/desktop/node_modules/dsh-langflow-flows-skill/skills/langflow-flows/scripts/install.sh
```

После этого скилл `langflow-flows` виден агенту; бандл остаётся в «Плагинах» как
способ доставки версии.

## Что внутри

```
cordis.patch.yml         попытка расширить customSkillDirs у skill-filesystem
skills/langflow-flows/   сам скилл: SKILL.md, справочники, примеры, скрипты, тесты
```

## Что дальше

Если в следующих сборках DSH `!!js` в бандл-патчах заработает, достаточно будет
проверить `customSkillDirs` и убрать ручной шаг из инструкции. Патч для этого
уже лежит в пакете.

MCP-сервер Langflow бандл не настраивает: у каждого свой адрес и ключ.
Строка для `cordis.patch.yml` профиля — в README репозитория.
