# dsh-langflow-flows-skill

Плагин-бандл DSH: ставит скилл `langflow-flows` и показывает его в разделе «Плагины».

Автор скилла — **Andrey Datsenko**.

## Что делает

Скилл лежит внутри пакета (`skills/langflow-flows`) и подключается к штатному провайдеру
скиллов DSH: строка `skill-filesystem` расширяется — к её `customSkillDirs` добавляется
каталог скиллов этого пакета. Путь считается от файла патча, ничего прописывать вручную
не нужно.

Почему расширение, а не второй провайдер: второй экземпляр того же модуля в профиле
не поднимается — плагин скиллов регистрируется один раз. Поэтому патч заменяет список
`customSkillDirs` целиком и **сохраняет в нём штатный каталог скиллов пресетов DSH**.

## Установка

```
plugin_manager: install_bundle, target = github:Tsarevish/langflow-flows#path:/bundle
```

Локально, из склонированного репозитория:

```
plugin_manager: install_bundle, target = file:<путь>/langflow-flows/bundle
```

После установки нужен **перезапуск приложения**: патч-слой профиля собирается при старте.
Проверка — в списке скиллов появился `langflow-flows`, в «Плагинах» — `dsh-langflow-flows-skill`.

Если скилл уже стоял вручную в `~/.dsh/skills`, копию лучше убрать: при совпадении имён
побеждает бандл (у него выше приоритет корня), но дубль в каталоге только путает.

## Что внутри

```
cordis.patch.yml         расширение customSkillDirs у skill-filesystem
skills/langflow-flows/   скилл: SKILL.md, справочники, примеры, скрипты, тесты
```

## Границы

Бандл ставит **только скилл**. MCP-сервер Langflow подключается отдельно: у каждого
свой адрес и ключ, их нельзя зашить в пакет. Строка для `cordis.patch.yml` профиля —
в README репозитория.
