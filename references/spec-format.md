# Формат spec

Компактная текстовая спецификация — основной способ отдать граф в Langflow.
Парсер детерминированный и терпимый к мелким огрехам, но разделы и отступы важны.

## Каркас

```
name: Имя флоу
description: Одна строка, зачем он

nodes:
  A: ChatInput
  B: Prompt Template
  C: ext:openai:OpenAIModelComponent@official

edges:
  A.message -> B.question
  B.prompt -> C.input_value

config:
  B.template: |
    Ответь на вопрос: {question}
```

## Разделы

| Раздел | Обязателен | Формат строки |
|---|---|---|
| `name:` | нет (но всегда ставь) | `name: <текст>` |
| `description:` | нет | `description: <текст>` |
| `nodes:` | **да** | `<ID>: <Тип компонента>` |
| `edges:` | если >1 узла | `<ID>.<выход> -> <ID>.<вход>` |
| `config:` | нет | `<ID>.<поле>: <значение>` |

`ID` в `nodes` — локальное имя для этой спеки (`A`, `Vhod`, `Model`), а не id узла в Langflow.
Langflow потом сам сделает id вида `ChatInput-ZQQih`.

## Правила, которые ломают сборку

**Имя типа — точная строка.** Пробелы и префиксы значимы:

- `Prompt Template` — с пробелом
- `ChatInput`, `ChatOutput` — слитно
- `ext:openai:OpenAIModelComponent@official` — расширение с `ext:` и `@official`
- `OpenAIModel`, `OpenAIRouter`, `ChatInputComponent` не были доступны на проверенных стендах; на другом стенде сверяй каталог

Проверяй через `search_component_types` / `describe_component_type`.

**Правая часть edge — только существующий вход.** Если порта нет в `inputs` у типа,
сборка упадёт. Частый случай: у `Prompt Template` `inputs: []`, пока в шаблоне нет
переменных. Появилась `{question}` → появился порт `question`.

**Слева — имя выхода.** Не подпись, не тип: `message`, `prompt`, `text_output`,
`model_output`, `response`, `component_as_tool`, `run_sql_query`.

**Ссылки на несуществующие ID** валят сборку целиком, а не построчно.

**Комментариев нет.** Строка, начинающаяся с `#`, — ошибка парсера
(`Unrecognized line`). Пояснения к спеке — в описании флоу или отдельным текстом рядом,
не в файле спеки.

## Значения в `config`

Приведение типов автоматическое:

| Написано | Станет |
|---|---|
| `true` / `false` | bool |
| `null` / `none` | None |
| `42` | int |
| `0.2` | float |
| `|` в начале значения | многострочная строка |

Многострочный текст — только через `|`, продолжение с отступом:

```
config:
  P.template: |
    Ты — аналитик.
    Отвечай только SQL.
```

**Чего в `config` не задать:**

- списки и объекты (например `operation` у `Operations` — это `sortableList`);
- служебные флаги вроде `load_from_db` (привязка к переменной);
- поля, помеченные как защищённые.

Для списков/объектов — `configure_component`, если его схема поддерживает значение.
Для credential-привязок — UI/подтверждённый API переменных или минимальный REST patch
с сохранением `load_from_db: true`; строковый `configure_component` привязку не создаёт.
Защищённые поля задаются в самом флоу по возможностям целевой версии.

## Чего в спеке нет вообще

| Нет | Почему это ок |
|---|---|
| координат узлов | раскладка считается автоматически: колонки по 480 px, ветки ±175 px |
| заметок на канвасе | добавляй отдельно, если попросят |
| привязки к переменным | UI/подтверждённый API переменных либо точечный `PUT` с `load_from_db: true` |
| позиций для ветвлений | тоже автоматически; `layout_flow` нужен после add/remove |

## Проверенный минимум

```
name: Минимум
description: Чат без модели

nodes:
  Vhod: ChatInput
  Otvet: ChatOutput

edges:
  Vhod.message -> Otvet.input_value
```

Такой флоу запускается и возвращает ровно то, что ввели. Это лучший способ проверить,
что связка «инструменты + инстанс» жива, до сборки чего-то сложного.


## Проверка и перенос

Spec — текстовый вход инструментов сборки, не JSON для импорта в интерфейс.
Офлайн можно подготовить spec и проверить её по снапшоту. Для импортируемого JSON
нужен совместимый builder либо экспорт созданного графа; этот скилл не содержит
офлайн-конвертера spec → Langflow JSON. Не генерируй закодированные handles вручную.
Многострочный текст после `|` должен иметь больший отступ, чем ключ. Слова `nodes:`,
`edges:` и `config:` внутри него остаются текстом. Разделы графа начинаются без отступа.
Неизвестные поля — ошибки; динамические порты/поля сначала обнови на стенде.

| Код | Значение |
|---|---|
| E001–E003 | нет узлов, ошибка синтаксиса, повтор ID |
| E004–E007 | неизвестный тип/узел/выход/вход |
| E008–E009 | неизвестный узел/поле config |
| E010 | имя credential-переменной записано как строковое значение |
| E011 | порт не объявлен переменной шаблона |
| E012 | несовместимые объявленные типы портов |
| E013 | обязательное поле без связи/значения/дефолта |
| W001 | переменная промпта без связи или config |
| W003–W005 | нет модели агента, неполное ветвление, нет chat/text-выхода |
| W006 | похожее на секрет значение в config, включая password-поля |
| W007–W009 | изолированный узел, нет пути к выходу, SQL без подключения |
| W010 | tool-порт предполагается, требуется проверка вызова |
| W011–W012 | динамическая схема либо обязательная привязка требуют live-проверки |
| W013 | от конкретного входа нет пути к выходу |

Все E имеют severity=error; W — warning. Предупреждение означает неопределённость
или ограничение, а не обещание успешного запуска. Старые снапшоты не знают дефолтов:
проверка обязательности по ним неполная. Динамическая конфигурация проверяется на стенде.
Проверка типов использует пересечение объявленных `types` и `input_types`; неявные
конверсии и наследование, не отражённые схемой, требуют live-подтверждения.
