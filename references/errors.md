# Диагностика

Сначала прочитай фактическую ошибку инструмента. На проверенных стендах причины
иногда отсутствовали, и тогда требовался отдельный запрос. Ниже — наблюдавшийся порядок,
который надо сверять с API целевой версии. `False` без `isError` также означает сбой.

## Порядок

1. **Симптом.** `run_flow` вернул `False` / `validate_flow` вернул `valid: false`.
2. **Версия.** Посмотри профиль стенда. На проверенном 1.13 `validate_flow` часто называл узел
   и причину — тогда шаг 3 не нужен. На проверенном 1.12 было общее `Build error`; использовался build-стрим.
   Если текущий ответ уже содержит причину, не запускай граф повторно ради диагностики.
3. **Структура.** `get_build_results` — какие узлы собрались. Если собрался только вход,
   падает первый же содержательный узел.
4. **Причина.** Build-стрим:

```
POST /api/v1/build/{flow_id}/flow?log_builds=true&event_delivery=direct
Accept: application/x-ndjson
```

Ответ — NDJSON, по объекту на строку. Нужные события:

| Событие | Что внутри |
|---|---|
| `vertices_sorted` | порядок узлов, которые пойдут в работу |
| `build_start` / `end_vertex` | прогресс |
| `add_message` | текст сообщений (в том числе ответ модели) |
| `error` | **причина**: `data.data.content_blocks[].contents[].reason` |
| `end` | завершение |

Причина лежит глубоко:

```
content_blocks[0].contents[0].reason = "**AuthenticationError**\n - **...**"
content_blocks[0].contents[0].traceback = "..."
```

4. **Вывод.** Переведи `reason` в действие: что именно поменять в узле.

## Каталог стенда

Полный список 43 поломок с точными текстами — в `guide.md` (раздел «Лимиты стенда»
и карточки блоков). Самые частые и их настоящие причины:

| Симптом | Причина | Что делать |
|---|---|---|
| `401 Unauthorized` | нет `OPENAI_API_KEY` или в ключе пробел | проверить переменную, тип Credential |
| `403 Forbidden` | ключ из другого каталога, чем в `model_name` | каталог в `gpt://<каталог>/…` и ключ должны совпадать |
| `403 unsupported_country_region_territory` | запрос ушёл в **настоящий** OpenAI: у агента нет связи с моделью, или на холсте блок Language Model | проверить `model_output → Agent.model` и `openai_api_base` |
| `404 model_not_found` | в поле модели имя из другого каталога или `emb://` | нужна языковая модель `gpt://…` |
| `'ascii' codec can't encode` | в ключе русские буквы (вставили подсказку вместо ключа) | перевписать ключ |
| Пустой ответ модели | `max_tokens` мало | поднять до ~3000 |
| `Model call limits exceeded (15/15)` | агент упёрся в `max_iterations` | поднять лимит ненадолго, искать причину зависания |
| `Recursion limit of 21 reached` | инструмент падает, агент повторяет вызов | запустить инструмент отдельно, починить его |
| `The truth value of a DataFrame is ambiguous` | в своём коде `if df` | `if df.empty` |
| `Permission denied` при записи файла | стенд запрещает запись | выводить в чат или свой блок со ссылкой |
| `No files to process` | файл не выбран после импорта | выбрать файл заново |
| `Column 'имя' not found in the DataFrame` | колонка называется иначе | взять имя из текста ошибки |
| `Регекс в If-Else не срабатывает` | проверка идёт с начала строки | начать шаблон с `(?s).*`, регистр — `(?i)` |
| `Поток остановился на первом блоке без ошибки` | выход If-Else вернули в промпт напрямую | нужен блок с портом `∞` (связка «цикл с возвратом») |
| `Skipped: no connected outputs` у Human Input | ни один вариант решения не подключён | подключить хотя бы один выход |
| `Error in loop iteration: …` | ошибка в одной строке останавливает цикл | проверять тело на одной строке |

## Разбор отдельных ошибок

### `AuthenticationError ... Unknown api key 'OPEN****_KEY'`

Причина: в поле ключа лежит **строка** `OPENAI_API_KEY`, а не значение переменной.
Сработало `configure_component` или `config` в спеке — они снимают `load_from_db`.

Лечение: `PUT /api/v1/flows/{id}` с полным `data`, в поле вернуть
`{"value": "OPENAI_API_KEY", "load_from_db": true}`.
Профилактика: не трогать поле вообще.

### `PermissionDeniedError — Country, region, or territory not supported`

Причина: модель OpenAI вызывается напрямую из региона, который OpenAI блокирует.
Лечение: `openai_api_base` на доступный OpenAI-совместимый шлюз (см. профиль стенда).

### `Unknown component: <Имя>`

Причина: имя типа написано «по смыслу». Правильно — точная строка из
`search_component_types`, например `Prompt Template`, а не `PromptComponent`.

Ответ инструмента содержит список доступных имён — читай его, а не угадывай.

### `Flow validation failed: Build error`, флоу не создан

Причина: `create_flow_from_spec` с `validate: true` упал на сборке.
Флоу при этом **не сохраняется**, следов не остаётся.
Лечение: создать с `validate: false` и разобрать причину build-стримом.

### `{"valid": false, "errors": [{"component_id": "flow", "error": "Build error"}]}`

Причина: обобщённая заглушка. Никакой конкретики здесь нет by design.
Лечение: build-стрим.

### `run_flow isError: True, текст "False"`

Причина: ошибка где-то внутри исполнения, инструмент её не пробрасывает.
Лечение: build-стрим по тому же флоу даст настоящий `reason`.

### Пустой ответ при «успешном» запуске

Проверять по порядку:

1. `ChatOutput` вообще подключён?
2. Промпт-узел: переменная в шаблоне совпадает с портом, в который соединено?
3. Поле `input_value` у `ChatInput` пустое — при запуске через API вход надо передавать
   явно (`input_value` в `run_flow`).
4. Модель вернула пустую строку — смотри `add_message` в стриме.

### Узел «не видит» файл

Файловые узлы работают с файлами, загруженными в сессию/флоу. При сборке через API
файл нужно приложить отдельно, иначе узел пуст и цепочка выглядит сломанной.

## Чего не делать при диагностике

- Не перезапускай флоу десять раз подряд с той же ошибкой — это не даёт новой информации.
  Три попытки, потом диагноз и вопрос пользователю.
- Не пересобирай весь флоу из-за одного узла: правь узел.
- Не «лечи» ошибку авторизации правкой промпта.


## Дополнено live-проверками 14.11.2026

Номер версии не гарантирует детализацию ошибки. На 1.12.2 `validate_flow` в одном
сценарии назвал отсутствующую переменную, а на 1.13.0 SQL-ошибка вернулась как общий
`Build error`. В проверенном ответе MCP при падении был `isError: true` с текстом
`Error executing tool run_flow: False`. Буквальный False без флага обработай как сбой,
но не утверждай, что сервер всегда возвращает именно такую форму.

Build-stream может содержать причину в `end_vertex.data.build_data.params`, когда
`valid: false`, либо в `data.outputs.<порт>.message.errorMessage/stackTrace`.
Смотри и `error`-события с content_blocks/reason, и невалидные end_vertex.
Стрим может быть NDJSON или JSON-событиями, разделёнными пустыми строками, без `data:`.
Не ограничивай разбор только SSE-префиксами.

`Database dialect 'sqlite' ... not permitted (LANGFLOW_RESTRICT_LOCAL_FILE_ACCESS=true)`
означает ограничение стенда. На проверенных 1.12.2/1.13.0 запрет распространяется и на
`sqlite:///:memory:`. Не отключай защиту ради теста и не подставляй рабочую БД:
для SQL-сценария требуется явно предоставленная тестовая сетевая БД.

### File после переноса 1.12.2 → 1.13.0

Загрузка txt на целевой сервер и `configure_component(path=[...])` не всегда достаточны.
В наблюдавшемся импортированном узле на 1.13.0 метод читал `template.path.file_path`,
хотя configure обновлял только `template.path.value`; результат — `No files to process`.
Проверь фактический template и обработчик целевой версии. После экспорта/checkpoint
можно обновить только `path.file_path` подтверждённым путём загруженного целевого файла,
затем перечитать, валидировать и проверить текст. Не переноси старый серверный путь.
Это наблюдение конкретного сценария, не универсальное требование для всех File-узлов.
