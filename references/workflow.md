# Сборка и приёмка

Правила контекста и вопросов — в `SKILL.md`; здесь детали сложных операций.

## Перед правкой

Прочитай актуальный граф и значения затронутых полей. Подтверждённые стенд, модель
и источники не уточняй повторно. Сохраняй незатронутые параметры.
Покажи короткий план соразмерно изменению и продолжай в рамках поручения.
Если нет необходимого доступа или неоднозначен целевой граф, дождись уточнения.
Для точечной правки используй конфигурацию/соединение конкретного узла.
Сохрани снимки до/после и проверь diff полного `data`, если пользователь просит
сохранить всё остальное. Служебный `updated_at` может измениться, но это не разрешает
перестраивать IDs, связи, код, координаты или credential-привязки.
Для полной замены сохрани экспорт и сравни актуальное состояние с исходным перед
записью. При конкурентных изменениях перечитай и пересчитай patch. Если API не имеет
условной записи, остаётся окно гонки: согласуй отсутствие параллельного редактирования
при полной замене. Для боевого сценария предпочтительна копия.
Не удаляй переменные, файлы, историю или другие флоу при откате.

## Сложный новый граф

Раздели архитектуру на проверяемые части. Для RAG сначала проверь чтение документа
и загрузку чанков, затем retrieval, затем ответ. Для агента сначала проверь инструмент
отдельно, затем его вызов агентом. Искусственный чат-скелет не обязателен.
До записи проверь spec, после — перечитай граф. Переиспользуй схему типа, пока
динамическая настройка, шаблон или tool mode не изменили порты.
Сохраняй checkpoint работающего состояния. Восстановление из приблизительной spec
может потерять поля, привязки, IDs и загрузки: нужен точный checkpoint/обратный patch.

## Проверки поведения

| Возможность | Проверка |
|---|---|
| Промпт/модель | смысл, формат ответа и сохранность выбранной модели |
| Инструмент | вызов в структурированном trace/build result и результат |
| Память | уникальный факт, извлечение в той же сессии, изоляция другой |
| Ветвление | обе ветки и соответствующий выходной узел |
| Файл | контрольный фрагмент, таблица/скан, если важны |
| RAG | чанки, релевантный retrieval, ответ с проверяемым источником |
| Правка | нужное изменение и сохранность остальных настроек |

`False`, пустой ответ и кэш не доказывают успешный запуск.
Упоминание инструмента в ответе не доказывает вызов. Нет trace — укажи «не подтверждён».
Session IDs и формат run API проверяй по схеме целевого сервера.

## Приёмка и перенос

Укажи ссылку/ID, тестовые входы, результат и ограничения. Раскладка — по необходимости,
`notify_done` — если доступен. Для передачи экспортируй поддерживаемым инструментом,
проверь отсутствие секретов и перечисли переменные, файлы, расширения и сервисы.
Офлайн выдаётся spec. JSON для импорта — только из совместимого builder/export
с проверкой на целевой версии. При отсутствии доступа продолжай независимую часть,
но не повторяй одинаковую неудачу больше трёх раз без новых данных.
