# Langflow Flows

Скилл для AI-агента, который создаёт, редактирует и диагностирует флоу в Langflow.
Он помогает выбрать компоненты, соединить их по схеме конкретного стенда,
сохранить настройки и проверить результат запуском.

**Автор:** Andrey Datsenko · **Версия:** 0.4.1

## Возможности

- Сборка чатов с моделью, цепочек промптов и агентов с инструментами.
- Изменение существующего флоу без полной пересборки.
- Поиск ошибок в компонентах, соединениях и настройках провайдера.
- Работа с файлами, памятью и ветвлением.
- Подготовка текстовой спецификации `.spec`, когда доступа к Langflow нет.

Скилл содержит инструкции и вспомогательные Python-скрипты. Он не устанавливает
Langflow и не подключает MCP автоматически. Для работы с графом нужен доступ
к инструментам сборки выбранного стенда.

## Что нужно для начала

1. Запущенный Langflow и API-ключ для доступа к нему.
2. AI-агент с поддержкой файловых скиллов и MCP-инструментов сборки Langflow.
3. Python 3.10 или новее для вспомогательных скриптов; дополнительных пакетов не требуется.
4. Для сценариев с моделью — настроенный провайдер и credential-переменная в Langflow.

Без модели можно проверить простое эхо: `ChatInput → ChatOutput`.

## Установка

Откройте каталог со `SKILL.md`. Все команды ниже, кроме раздела о разработке,
выполняются из этого каталога.

### DSH на Windows

```powershell
powershell -ExecutionPolicy Bypass -File scripts/install.ps1
```

По умолчанию скилл устанавливается в `%USERPROFILE%\.dsh\skills\langflow-flows`.
Чтобы выбрать другой каталог:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/install.ps1 -Target "D:\skills\langflow-flows"
```

### macOS и Linux

```bash
bash scripts/install.sh
```

Другой каталог можно передать первым аргументом:

```bash
bash scripts/install.sh ~/.dsh/skills/langflow-flows
```

Установщики обновляют файлы скилла и сохраняют существующие профили стендов.
После установки убедитесь, что агент видит скилл `langflow-flows`.
При доставке через DSH bundle может понадобиться этот же ручной шаг установки:
автоматическая регистрация патчем не работала в проверенной сборке DSH.
Подробности и команда для каталога пакета приведены в README бандла.
Для другого агента поместите каталог скилла в поддерживаемое им хранилище навыков.

## Подключение к Langflow

Подключение MCP настраивается отдельно для каждого стенда. Пример для DSH:

```yaml
- insert:
    - id: langflow-mcp
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: langflow
        transport: streamable-http
        url: 'http://127.0.0.1:7860/api/v1/agentic/mcp'
        headers:
          x-api-key: '<API-ключ Langflow>'
        failOnStartupError: false
        toolCallTimeoutMs: 180000
```

Замените адрес и ключ своими значениями. Ключ храните в приватной конфигурации
подключения; не добавляйте её в репозиторий.

Проверьте, что подключение предоставляет инструменты создания и изменения графа,
например `describe_component_type` и `create_flow_from_spec`. MCP-сервер,
который только публикует готовые флоу как инструменты, для сборки графов недостаточен.
Имена и состав инструментов зависят от версии и настроек сервера.

## Первый запуск

Начните с небольшой задачи:

> Используй langflow-flows. На локальном стенде создай эхо-флоу без модели
> и проверь, что он возвращает введённый текст.

Для задачи с моделью укажите стенд, если он ещё не выбран:

> На удалённом стенде собери чат с рабочей моделью из профиля.
> Ответы должны приходить в Playground.

Для изменения графа укажите его ID или ссылку и нужное изменение:

> Во флоу <ID> поменяй только температуру на 0.2. Остальные настройки сохрани.

Агент использует уже известные стенд, модель и источники. Он уточняет только то,
без чего нельзя выбрать правильное действие, и сообщает, что фактически проверил.

## Профиль стенда

Профиль хранит сведения о конкретной установке: версию, доступные компоненты,
рабочую модель, лимиты и особенности. Он нужен, поскольку схемы разных стендов
могут отличаться даже при одинаковой версии Langflow.

Передайте адрес и API-ключ через окружение и снимите профиль:

```powershell
$env:LANGFLOW_URL = 'http://127.0.0.1:7860'
$env:LANGFLOW_API_KEY = '<API-ключ Langflow>'
python scripts/probe_stand.py
```

Вместо окружения можно использовать приватный файл `~/.langflow/env`:

```text
LANGFLOW_URL=http://127.0.0.1:7860
LANGFLOW_API_KEY=<API-ключ Langflow>
```

Для другого файла: `python scripts/probe_stand.py --env <путь-к-файлу>`.
Ключ не нужно передавать агенту в сообщении или указывать в аргументах команды.

В каталоге `profiles/stand-<адрес>/` появятся:

| Файл | Назначение |
|---|---|
| `profile.md` | Ручные настройки: рабочая модель, ограничения и особенности |
| `profile.auto.md` | Измеренные сведения последней успешной разведки |
| `profile.json` | Машинное представление профиля |
| `components.json` | Снапшот схем для офлайн-валидатора |

Дополните `profile.md` сведениями, которые нельзя получить через API.
Повторная разведка сохраняет ручную карточку, `limits`, `quirks` и дополнительные
поля JSON. Если схемы не загрузились, предыдущий снапшот не заменяется пустым.
После смены версии или набора расширений обновите профиль.

## Проверка спецификации

Перед отправкой графа на сервер можно проверить `.spec` по снапшоту нужного стенда:

```text
python scripts/validate_spec.py examples/01-echo.spec --profile profiles/<стенд>
```

Дополнительные режимы:

```text
python scripts/validate_spec.py flow.spec --profile profiles/<стенд> --strict
python scripts/validate_spec.py flow.spec --profile profiles/<стенд> --format json
```

Валидатор проверяет типы компонентов, порты, совместимость объявленных типов,
поля конфигурации и часть обязательных настроек. Ошибки `E*` блокируют отправку;
предупреждения `W*` требуют оценки. В режиме `--strict` предупреждения тоже блокируют проверку.

Офлайн-валидация не подтверждает доступ к модели, файлам или БД и не заменяет запуск.
Формат спецификации и коды проверок описаны в [справочнике spec](references/spec-format.md).

## Тесты

Локальные регрессионные тесты не требуют Langflow или реального профиля:

```text
python tests/run_tests.py
```

Интеграционные проверки запускаются с явным режимом:

```text
python tests/run_eval.py --check-only --profile profiles/<стенд>
python tests/run_eval.py 01 --live --profile profiles/<стенд>
```

`--check-only` проверяет структуру без сети. `--live` создаёт, запускает и удаляет
временные тестовые графы. Для модельных сценариев нужны дополнительные настройки;
см. [инструкцию по live-тестам](tests/eval/README.md).

Отдельный [набор задач для независимого агента](tests/behavior/README.md) оценивает
решение задачи по формулировке пользователя, без готовой spec.
Фактические результаты и ограничения проверок — в [VERIFICATION.md](VERIFICATION.md).

## Ограничения и переносимость

- В офлайн-режиме результат — непроверенная `.spec`, а не JSON для импорта в интерфейс.
  Для JSON нужен совместимый builder или экспорт созданного графа.
- Перенос графа не переносит автоматически файлы, credential-переменные и расширения.
  Эти зависимости нужно подготовить на новом стенде.
- Поддержка RAG, форматов файлов и кастомных компонентов зависит от установки.
  Наличие инструкции в справочнике не означает, что сценарий проверен на вашем стенде.
- Проверки памяти и инструментов требуют доказательств поведения: одного правильного
  ответа недостаточно.

## Для разработки скилла

В рабочем репозитории исходный скилл находится в `skill/`. Из корня проекта:

```text
python tools/build_distribution.py
python tools/verify_distribution.py
```

Сборка обновляет `dist/langflow-flows-skill/` и вложенный DSH bundle.
Проверка запускает тесты обеих копий в изолированных каталогах без реальных профилей.
Эти команды не публикуют пакет и не меняют подключения Langflow.
