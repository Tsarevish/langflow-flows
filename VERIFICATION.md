# Проверено

Журнал: что запускалось, на чём и с каким результатом. Дата: 13.11.2026.

Проверено на двух установках Langflow:

| Установка | Версия | Роль в проверке |
|---|---|---|
| серверная (Linux, удалённый адрес) | 1.12.2 | основной рабочий стенд с базой данных |
| локальная (Windows, Langflow Desktop) | 1.13.0 | контроль версии и локального размещения |

## Разделение ответственности

| Слой | Что содержит | Откуда взят |
|---|---|---|
| `SKILL.md`, `references/*` | правила Langflow, не зависящие от установки | проверки на стендах + документация |
| `profiles/<стенд>/` | версия, провайдеры, модель, лимиты, запреты | `probe_stand.py` + опыты + слова эксплуатации |
| `profiles/<стенд>/components.json` | имена компонентов и портов этой версии | снято запросом |
| `tests/` | проверка валидатора | прогоны |

Правило: установочный факт, попавший в `references/`, — ошибка. Такие факты живут
только в профиле.

## Снятие профиля

`probe_stand.py` на серверной установке определил: версию 1.12.2, роль без прав суперюзера,
флаги (`allow_custom_components: true`, `authz_enabled: false`), 9 провайдеров-шаблонов,
2 настроенные переменные, встроенный MCP с 31 инструментом, 178 типов компонентов.

На локальной: 1.13.0, 32 инструмента MCP (добавлен `run_assistant`), 341 тип компонентов,
`event_delivery: polling` вместо `streaming`.

Что скрипт **не** определяет и заполняется вручную: лимит времени запуска,
параллельность запросов, политика записи файлов, читаемые форматы, доступ в интернет,
модели с поддержкой изображений. Рецепты проверки — `references/recon.md`.

**Найденный дефект probe.** На 1.13 `/api/v1/all` содержит категорию
`component_display_names` — это переводы подписей (341 запись), а не компоненты.
Скрипт её отбрасывает; без этого снапшот распухал вдвое и валидатор считал «компонентом»
строку `chatinput`.

## Поведение на другой версии

Одни и те же спеки прогнаны на 1.12.2 и 1.13.0:

| Проверка | 1.12.2 | 1.13.0 |
|---|---|---|
| `create_flow_from_spec` + авто-раскладка | 0, 480, 960… | так же |
| `run_flow` на простом флоу | ответ получен | ответ получен |
| `api_key` у модели по умолчанию | `load_from_db: true` | так же |
| `validate_flow` при ошибке | `component_id: "flow"`, `error: "Build error"` | называет узел и причину |
| инструменты MCP | 31 | 32, добавлен `run_assistant` |

## Опыты на локальной установке

| Что | Результат |
|---|---|
| Модель через OpenAI-совместимый шлюз | работает: короткий ответ получен |
| Запись файлов | разрешена: `SaveToFile` вернул путь в кэше приложения |
| Выход в интернет | есть: `APIRequest` вернул `status_code: 200` |
| База данных | нет: `SQLComponent` подключать некуда |

Побочная находка: `Set-Content -Encoding utf8` в Windows PowerShell пишет BOM, и валидатор
падал на первой строке. Парсер теперь снимает BOM — спеки, сохранённые виндовым
редактором, проверяются нормально.

## Что не проверялось

- RAG: retriever, vector store, embeddings — не было настроенного эмбеддера.
- Многоагентные схемы и кастомные компоненты.
- Многострочные SQL и ошибки прав в БД.
- Версии Langflow, кроме 1.12.2 и 1.13.0.
- `probe_stand.py` на установке с нестандартной аутентификацией.
